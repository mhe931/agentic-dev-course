# Exercise 7.1: Built-in Orchestration

## Objective
See how Copilot can delegate work to a sub-agent using nothing but a chat prompt — demonstrating built-in orchestration without custom agent files.

## Background
Before building a custom orchestration framework with `.agent.md` files, it's worth seeing what Copilot can do out of the box. A single prompt can instruct Copilot to spawn a sub-agent that calls external MCP tools and returns results. This is the simplest form of orchestration: one coordinator (your prompt), one (or more) sub-agents with a specific task. You'll use this to check your code against official library documentation using Context7.

## Prerequisites

> **Prerequisite:** Sub-agent delegation requires the `agent/runSubagent` tool — enabled in the Chat **tools picker** (the tools icon in the chat input). If it's unchecked, the "use a sub-agent" prompt below will run everything in the main session instead of delegating.

The **Context7 MCP server** should already be configured in your project from [Exercise 5.1](../../05-mcps-and-integrations/exercises/01-find-and-configure-mcps.md). If not, go back and complete that exercise first.

## Steps

1. **Pick a file with library imports.** Choose a file from your project that imports external libraries (e.g., an Express route file, a React component, a FastAPI endpoint).

2. **Run a doc-check prompt.** In Agent mode, paste the following prompt:

   ```
   For each external library imported in [your file], spawn a SEPARATE sub-agent to:
   1. Resolve the library to its official Context7 documentation ID
   2. Query the official docs for best practices, patterns, and guidelines
   3. Return findings about that specific library

   Then, synthesize all sub-agent reports and:
   - Check the code against all documentation findings
   - Report any deprecated APIs, missing best practices, version-specific issues,
     outdated patterns, or missing error handling
   - Cite documentation sources for each finding
   ```

3. **Observe sub-agent spawning.** Watch the Copilot output for signs of delegation — you should see one sub-agent per detected library, each calling Context7's `resolve-library-id` and `query-docs` tools for its library, followed by the main agent's synthesis. Note: the sub-agent delegation may not always be visually distinct from the main agent's work, and the agent may still batch libraries into fewer sub-agents than asked. Focus on the MCP tool calls appearing in the output.

4. **Evaluate the report.** Are the findings backed by specific documentation references? Are the file/line locations accurate? Did it cover all the libraries in your file?

5. **Reflect: plain prompts vs. agent files.** This prompt gave you orchestration "for free" — no YAML frontmatter, no tool scoping, no model selection. Consider the trade-offs:
   - **Strengths**: Zero setup beyond the MCP server. Quick to iterate — just edit the prompt and re-run.
   - **Limits**: No control over which model the sub-agent uses. No tool scoping. No persistent agent identity.
   - These limits are exactly what the custom `.agent.md` framework in Exercises 7.2–7.3 solves.

## Expected Outcome
A documentation compliance report generated by Copilot using Context7, with evidence of MCP tool invocations in the output. You understand what a plain prompt can orchestrate and where custom agent files provide more control.
